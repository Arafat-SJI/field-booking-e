# Field Booking Site

A runnable **full-stack monorepo** generated by the **AI Project Builder**
from reusable modules in the base repository (`sjinnovation/base`).

Layout: `client/` (Next.js App Router) + `server/` (Node.js API) + `supabase/` at repo root.

## Getting started

```bash
npm install
cp .env.example .env.local   # fill in the values below
npm run dev                  # Next.js on http://localhost:3000
npm run dev:server           # API on http://localhost:4000 (separate terminal)
```

## Routes

- [`/login`](/login) — Login
- [`/signup`](/signup) — Sign up

## Modules included

- **Login / User Management** (`login-user-management`) — Client requires Login and Registration pages with specific UI elements, form inputs, password management, and account creation flows. This module provides full-stack authentication, user management, and UI components for login and signup.

## Supabase

- Apply the SQL migrations under `supabase/migrations/` to your Supabase project.
- Deno edge functions (if any) live under `supabase/functions/` and deploy separately.

## Manual follow-ups

- Wire a Supabase browser client at client/lib/supabaseClient (export named `supabase`) and a server service key for server routes.
- Run the supabase migrations and deploy functions from the module's supabase/ folder (copied by pipeline) into your project; do not commit secrets.
- Protect or disable the create-admin edge function after bootstrapping your first admin in production.
- This package expects shadcn-style UI components at '@/components/ui/*' — replace or implement those primitives as needed.
- Monorepo layout: run `npm install` at repo root, then `npm run dev` for client and `npm run dev:server` for API.
- Set API_BASE_URL in .env.local (e.g. http://localhost:4000) so the client can reach the server.

See `PROJECT-MANIFEST.json` for the full machine-readable selection.
